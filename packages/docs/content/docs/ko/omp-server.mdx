# OMPChamber 서버

OMPChamber는 OMPChamber 서버 위에서 실행됩니다. 기본적으로 OMPChamber가 서버를 직접 시작하므로 따로 할 일은 없습니다. OMPChamber가 시작한 서버를 관리하려는 경우에만 이 페이지가 필요합니다.

## OMPChamber가 서버를 찾는 방법

OMPChamber가 시작되면 다음 순서로 서버를 찾습니다.

1. 이미 시작한 서버를 재사용합니다
2. 기본 포트(`4096`)에서 서버를 자동으로 감지합니다
3. 그 외에는 자체 서버를 시작하고 관리합니다

아무것도 설정하지 않으면 3단계가 자동으로 실행되어 바로 사용할 수 있습니다.

## CLI에서 서버 관리하기

```bash
ompchamber status
ompchamber logs
ompchamber restart
ompchamber stop
```

`ompchamber`만 입력하면 서버가 백그라운드에서 시작됩니다. 터미널에 연결된 상태로 유지하려면 `--foreground`를 추가하세요.

## 로그인할 때 OMPChamber 시작하기

`startup enable`을 사용해 네이티브 사용자 서비스를 설치하세요. OMPChamber는 macOS에서 `launchd`, Linux에서 `systemd --user`, Windows에서 Task Scheduler를 사용합니다.

```bash
ompchamber startup enable
ompchamber startup status
ompchamber startup disable
```

UI를 보호하려면 서비스를 활성화할 때 비밀번호를 설정하세요:

```bash
OMPCHAMBER_UI_PASSWORD='secret' ompchamber startup enable
```

로그인 시 시작되고 데스크톱 또는 모바일 앱에서 사용할 headless 서버라면 `--api-only`와 접근 가능한 host를 함께 지정하세요:

```bash
ompchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable`은 현재 환경의 스냅샷을 서비스에 저장해, 같은 셸에서 `ompchamber`를 직접 실행한 것에 더 가깝게 동작하게 합니다. provider 토큰, `PATH`, SSH agent 설정, 기타 CLI auth/config 환경 변수가 유지됩니다. 최소한의 서비스 환경을 원하면 `--no-env-snapshot`을 사용하세요.

시작 서비스는 `--port`, `--host`, `--ui-password`, `--api-only`를 기억합니다. CLI 재시작과 업데이트 재시작은 이 저장된 설정을 다시 사용합니다.

다른 OMPChamber 앱용 연결 링크를 만들려면 다음을 사용하세요:

```bash
ompchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

`ompchamber connect-url --help`를 실행하면 `--name`, `--lan`, `--server`, `--api-only`, `--ui-password`, `--qr` 같은 모든 링크 옵션을 볼 수 있습니다.

실행 중인 이 서비스의 터널은 별도로 관리할 수 있습니다:

```bash
ompchamber tunnel start --port 3000
ompchamber tunnel stop --port 3000
```

터널을 중지해도 서비스나 앱은 재시작되지 않습니다.

## "OMP is restarting"

서버가 시작되거나 재시작되는 동안 OMPChamber는 "OMP is restarting" 상태를 표시하고 준비가 끝날 때까지 요청을 일시 중지합니다. 실행 직후나 재시작 직후에는 정상적인 동작입니다. 이 상태가 계속 사라지지 않으면 [OMP 연결](/ko/troubleshooting/omp-connection/)을 참고하세요.
