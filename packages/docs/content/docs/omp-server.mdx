# OMPChamber Server

OMPChamber runs on top of an OMPChamber server. By default it starts one for you, so you don't have to do anything. You only need this page if you want to manage the server it starts.

## How OMPChamber finds a server

When OMPChamber starts, it looks for a server in this order:

1. reuse a server it already started
2. auto-detect a server on the default port (`4096`)
3. otherwise, start and manage its own

If nothing is configured, step 3 happens automatically and you're up and running.

## Manage the server from the CLI

```bash
ompchamber status
ompchamber logs
ompchamber restart
ompchamber stop
```

`ompchamber` on its own starts the server in the background. Add `--foreground` to keep it attached to your terminal.

## Start OMPChamber at login

Use `startup enable` to install a native user service. OMPChamber uses `launchd` on macOS, `systemd --user` on Linux, and Task Scheduler on Windows.

```bash
ompchamber startup enable
ompchamber startup status
ompchamber startup disable
```

To protect the UI, set the password when enabling the service:

```bash
OMPCHAMBER_UI_PASSWORD='secret' ompchamber startup enable
```

For a headless server that starts at login and is meant for desktop or mobile clients, include `--api-only` and a reachable host:

```bash
ompchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` snapshots your current environment into the service so it behaves more like starting `ompchamber` from the same shell. This keeps provider tokens, `PATH`, SSH agent settings, and other CLI auth/config variables available. Use `--no-env-snapshot` if you want a minimal service environment.

The startup service remembers `--port`, `--host`, `--ui-password`, and `--api-only`. CLI restart and update restart reuse those saved settings.

To create a connection link for another OMPChamber app, use:

```bash
ompchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

Run `ompchamber connect-url --help` to see all link options, including `--name`, `--lan`, `--server`, `--api-only`, `--ui-password`, and `--qr`.

You can still manage tunnels independently for that running service:

```bash
ompchamber tunnel start --port 3000
ompchamber tunnel stop --port 3000
```

Stopping the tunnel does not restart the service or the app.

## "OMP is restarting"

While the server is starting or restarting, OMPChamber shows an "OMP is restarting" state and pauses requests until it's ready. This is normal right after launch or a restart. If it never clears, see [OMP connection](/troubleshooting/omp-connection/).
