# OMPChamber Server

O OMPChamber roda sobre um servidor OMPChamber. Por padrão, ele inicia um para você, então não precisa fazer nada. Você só precisa desta página se quiser gerenciar o servidor que ele inicia.

## Como o OMPChamber encontra um servidor

Quando o OMPChamber inicia, ele procura por um servidor nesta ordem:

1. reutilizar um servidor que ele já iniciou
2. detectar automaticamente um servidor na porta padrão (`4096`)
3. caso contrário, iniciar e gerenciar o seu próprio

Se nada estiver configurado, o passo 3 acontece automaticamente e você já está pronto para usar.

## Gerenciar o servidor pela CLI

```bash
ompchamber status
ompchamber logs
ompchamber restart
ompchamber stop
```

`ompchamber` sozinho inicia o servidor em segundo plano. Adicione `--foreground` para mantê-lo anexado ao seu terminal.

## Iniciar o OMPChamber no login

Use `startup enable` para instalar um serviço nativo do usuário. O OMPChamber usa `launchd` no macOS, `systemd --user` no Linux e Task Scheduler no Windows.

```bash
ompchamber startup enable
ompchamber startup status
ompchamber startup disable
```

Para proteger a UI, defina a senha ao habilitar o serviço:

```bash
OMPCHAMBER_UI_PASSWORD='secret' ompchamber startup enable
```

Para um servidor headless que inicia no login e é usado por apps desktop ou mobile, inclua `--api-only` e um host acessível:

```bash
ompchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` salva um snapshot do ambiente atual no serviço para que a inicialização se pareça mais com executar `ompchamber` na mesma shell. Isso preserva tokens de provedores, `PATH`, configurações do agente SSH e outras variáveis CLI de auth/config. Use `--no-env-snapshot` se quiser um ambiente de serviço mínimo.

O serviço de inicialização lembra `--port`, `--host`, `--ui-password` e `--api-only`. Reinícios pela CLI e reinícios durante atualização reutilizam essas configurações salvas.

Para criar um link de conexão para outro app OMPChamber, use:

```bash
ompchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

Execute `ompchamber connect-url --help` para ver todas as opções de link, incluindo `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` e `--qr`.

Você ainda pode gerenciar túneis de forma independente para esse serviço em execução:

```bash
ompchamber tunnel start --port 3000
ompchamber tunnel stop --port 3000
```

Parar o túnel não reinicia o serviço nem o app.

## "OMP is restarting"

Enquanto o servidor está iniciando ou reiniciando, o OMPChamber mostra um estado "OMP is restarting" e pausa as requisições até ele estar pronto. Isso é normal logo após a inicialização ou um reinício. Se nunca sair desse estado, veja [Conexão com o OMP](/pt-br/troubleshooting/omp-connection/).
