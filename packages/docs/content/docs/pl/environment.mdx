# Zmienne środowiskowe

OMPChamber odczytuje te zmienne przy starcie. Dla usług startowych `ompchamber startup enable` domyślnie zapisuje snapshot bieżącego środowiska, więc uruchom tę komendę ponownie po zmianie zmiennych, których ma używać usługa.

## Serwer OMPChamber

### `OMPCHAMBER_HOST`

Adres, na którym nasłuchuje serwer web OMPChamber. Użyj `0.0.0.0`, aby pozwolić na dostęp z innych maszyn.

### `OMPCHAMBER_UI_PASSWORD`

Hasło do interfejsu w przeglądarce. Ustaw je przy dostępie spoza localhost, tunelach albo reverse proxy.

### `OMPCHAMBER_API_ONLY`

Uruchamia OMPChamber w trybie headless, gdy ustawione na `true` lub `1`. Trasy API pozostają dostępne dla klientów desktopowych i mobilnych, ale UI przeglądarki nie jest serwowane.

### `OMPCHAMBER_DATA_DIR`

Nadpisuje katalog danych OMPChamber. Domyślnie jest to `~/.config/ompchamber`.

### `OMPCHAMBER_COMPRESS_API`

Steruje kompresją odpowiedzi API. `true` albo `1` ją włącza, `false` albo `0` wyłącza.

### `OMPCHAMBER_SKIP_API_COMPRESSION`

Wyłącza kompresję odpowiedzi API, gdy ma wartość `true` albo `1`. Ma pierwszeństwo przed `OMPCHAMBER_COMPRESS_API`.

### `OMPCHAMBER_VERBOSE_REQUEST_LOGS`

Włącza szczegółowe HTTP request logs, gdy ma wartość `true` albo `1`.

### `OMPCHAMBER_UPDATE_API_URL`

Nadpisuje endpoint sprawdzania aktualizacji. Większość użytkowników nie powinna tego ustawiać.

### `OMPCHAMBER_PACKAGE_MANAGER`

Wymusza package manager używany do aktualizacji, gdy automatyczne wykrywanie się pomyli.

## Serwer OMP

### `OPENCODE_PORT`

Ustawia port OMP server. Dla managed OMP prosi o ten port.

### `OMP_BINARY`

Ścieżka do executable `omp`, którego ma używać OMPChamber.

### `OPENCODE_BINARY`

Przestarzały alias dla `OMP_BINARY`, wciąż obsługiwany jako fallback.

### `OPENCODE_CONFIG`

Ścieżka do konkretnego pliku config OMP.

### `OPENCODE_CONFIG_DIR`

Ścieżka do katalogu config OMP dla agents, skills, snippets i config discovery.

### `OPENCODE_DATA_DIR`

Własny katalog danych dla managed OMP server.

### `OPENCODE_WSL_DISTRO`

Wybiera WSL distro używane do integracji OMP w Windows.

### `OMPCHAMBER_OPENCODE_WSL_DISTRO`

Alias specyficzny dla OMPChamber do wyboru WSL distro. `OPENCODE_WSL_DISTRO` ma pierwszeństwo, gdy ustawione są obie zmienne.

### `OPENCODE_JWT_SECRET`

Secret używany do podpisywania UI auth tokens. Dla trwałych usług użyj długiej losowej wartości.

## Terminal i Git

### `OMPCHAMBER_TERMINAL_SHELL`

Shell executable używany przez terminal sessions w OMPChamber.

### `OMPCHAMBER_GIT_BINARY`

Git executable używany przez funkcje Git w OMPChamber.

### `GIT_BINARY`

Alternatywny override dla Git executable. Dla konfiguracji specyficznej dla OMPChamber preferuj `OMPCHAMBER_GIT_BINARY`.

### `OMPCHAMBER_GIT_READ_CACHE_TTL_MS`

TTL w milisekundach dla cached Git-backed file reads. Ustaw `0`, aby wyłączyć cache podczas debugowania.

## Głos i tunele

### `OPENAI_API_KEY`

API key używany przez funkcje głosowe OMPChamber, które wywołują OpenAI-compatible services.

### `OMPCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Pozwala na zdalne OpenAI-compatible base URLs dla funkcji głosowych, gdy ma wartość `true` albo `1`.

### `NGROK_AUTHTOKEN`

ngrok auth token używany przez tunnel commands OMPChamber. Możesz też skonfigurować go przez `ngrok config add-authtoken <token>`.

## Runtime helpers

### `BUN_BINARY`

Bun executable, którego OMPChamber ma używać do uruchamiania daemon processes.

### `BUN_INSTALL`

Katalog główny instalacji Bun. OMPChamber używa go, aby znaleźć `bin/bun` dla daemon startup i aktualizacji.

### `VITE_OPENCODE_URL`

Build-time API base URL dla Vite-built web app. Przy normalnym użyciu CLI lub desktop większość użytkowników nie powinna tego ustawiać.
