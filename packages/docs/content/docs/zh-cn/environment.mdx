# 环境变量

OMPChamber 会在启动时读取这些变量。对于开机启动服务，`ompchamber startup enable` 默认会保存当前环境的 snapshot，所以如果要让服务使用新的变量，请重新运行它。

## OMPChamber 服务器

### `OMPCHAMBER_HOST`

OMPChamber web 服务器监听的地址。使用 `0.0.0.0` 可允许其他机器访问。

### `OMPCHAMBER_UI_PASSWORD`

浏览器 UI 的密码。当你绑定到 localhost 之外、使用隧道或反向代理时，请设置它。

### `OMPCHAMBER_API_ONLY`

设置为 `true` 或 `1` 时，以 headless 模式启动 OMPChamber。桌面和移动客户端仍可使用 API 路由，但不会提供浏览器 UI。

### `OMPCHAMBER_DATA_DIR`

覆盖 OMPChamber 数据目录。默认是 `~/.config/ompchamber`。

### `OMPCHAMBER_COMPRESS_API`

控制 API 响应压缩。`true` 或 `1` 强制开启，`false` 或 `0` 强制关闭。

### `OMPCHAMBER_SKIP_API_COMPRESSION`

设置为 `true` 或 `1` 时关闭 API 响应压缩。它优先于 `OMPCHAMBER_COMPRESS_API`。

### `OMPCHAMBER_VERBOSE_REQUEST_LOGS`

设置为 `true` 或 `1` 时启用详细 HTTP request logs。

### `OMPCHAMBER_UPDATE_API_URL`

覆盖更新检查 API endpoint。大多数用户不需要设置它。

### `OMPCHAMBER_PACKAGE_MANAGER`

当自动检测错误时，强制指定更新操作使用的 package manager。

## OMP 服务器

### `OPENCODE_PORT`

设置 OMP server 端口。对于 managed OMP，它请求使用该端口。

### `OMP_BINARY`

OMPChamber 应该运行的 `omp` executable 路径。

### `OPENCODE_BINARY`

`OMP_BINARY` 的 deprecated alias，仍然作为 fallback 被支持。

### `OPENCODE_CONFIG`

指定 OMP config 文件路径。

### `OPENCODE_CONFIG_DIR`

指定 OMP config 目录，用于 agents、skills、snippets 和 config discovery。

### `OPENCODE_DATA_DIR`

managed OMP server 的自定义数据目录。

### `OPENCODE_WSL_DISTRO`

选择 Windows 上 OMP 集成使用的 WSL distro。

### `OMPCHAMBER_OPENCODE_WSL_DISTRO`

OMPChamber 专用的 WSL distro alias。如果两个变量都设置，`OPENCODE_WSL_DISTRO` 优先。

### `OPENCODE_JWT_SECRET`

用于签名 UI auth tokens 的 secret。持久服务部署应使用长的随机值。

## Terminal 和 Git

### `OMPCHAMBER_TERMINAL_SHELL`

OMPChamber terminal sessions 使用的 shell executable。

### `OMPCHAMBER_GIT_BINARY`

OMPChamber Git 功能使用的 Git executable。

### `GIT_BINARY`

Git executable 的备用 override。OMPChamber 专用配置建议使用 `OMPCHAMBER_GIT_BINARY`。

### `OMPCHAMBER_GIT_READ_CACHE_TTL_MS`

Git-backed file reads cache 的 TTL，单位为毫秒。调试时可设置为 `0` 禁用 cache。

## 语音和隧道

### `OPENAI_API_KEY`

OMPChamber 语音功能调用 OpenAI-compatible services 时使用的 API key。

### `OMPCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

设置为 `true` 或 `1` 时，允许语音功能使用远程 OpenAI-compatible base URLs。

### `NGROK_AUTHTOKEN`

OMPChamber tunnel commands 使用的 ngrok auth token。也可以用 `ngrok config add-authtoken <token>` 配置。

## Runtime helpers

### `BUN_BINARY`

OMPChamber 启动 daemon processes 时使用的 Bun executable。

### `BUN_INSTALL`

Bun 安装根目录。OMPChamber 使用它查找 `bin/bun` 来启动 daemon 和执行更新。

### `VITE_OPENCODE_URL`

Vite-built web app 的 build-time API base URL。普通 CLI 或 desktop 使用通常不需要设置它。
